# Owner acceptance in approved Chrome

Use the required branch in a Chrome installation that allows unpacked extensions. Keep a backup of existing extension data; do not clear ordinary user storage. No cloud destination is needed for launch tests. Do not use a policy workaround.

1. Fresh profile: load the `extension` directory using Chrome Extensions → Developer mode → Load unpacked. Check Chrome's Errors section and the service-worker console. Pin REDOWN; on a normal HTTPS page click it. Expect the Shelf, no popup or extra tab. Check local navigation while disconnected.
2. Upgrade profile: reload the new source over the existing extension with the same ID. An old Popup preference must migrate to Shelf; profiles, destinations and History remain. Repeat toolbar opening after restarting Chrome.
3. Forced Shelf rejection: in a disposable test installation, open service-worker DevTools, save `const savedOpen = chrome.sidePanel.open`, then assign `chrome.sidePanel.open = () => Promise.reject(new Error('test rejection'))`. Click the actual toolbar icon. Expect the compact REDOWN recovery window and explanation. Dashboard, connection management and Settings must remain available. Settings opens only when explicitly requested.
4. Click rapidly several times. Expect one recovery window. Close it, click again, and expect one replacement. Restore `chrome.sidePanel.open = savedOpen`; click Retry Shelf in recovery. Expect the Shelf opening request to work. Do not call sidePanel.open directly from the console as a substitute for a real gesture.
5. Initialization failure: in the disposable source copy temporarily add a throw at the start of `shelf.js`, reload, then click the toolbar. Expect bounded recovery. Restore the source and reload. A provider timeout alone must not cause recovery if local Shelf controls are initialized.
6. On an ordinary HTTPS page right-click page space, a link and an image. With no destinations expect REDOWN setup/manage. With valid saved destinations verify Simple, Narrow and Level at existing depth; do not change cloud authorization solely for this test. Restricted Chrome pages are not acceptance targets.
7. In disposable worker DevTools wrap `chrome.contextMenus.create` to fail once for a new destination ID, retaining the original method. Change/apply a destination using the existing editor. Expect truthful Retry Apply and retained root/Manage. Restore the API and retry Apply. Confirm actual menu structure; a callback receipt alone is insufficient.
8. Stop/suspend the worker using Chrome's available extension inspection controls with DevTools closed, then click toolbar and right-click again. Repeat with browser restart, changed tabs, two browser windows and an already-open Shelf. Check that recovery belongs to the intended window and no extra windows accumulate.
9. Keep Chrome disconnected/offline and repeat toolbar/navigation. Repeat with a saved Cloudflare login that cannot reach its provider. Shelf opening must not wait for provider requests. Never export provider tokens or raw console objects.
10. In the recovery window use Export support report. It contains entry-point evidence and menu state only. Alternatively, in extension DevTools inspect `await chrome.storage.local.get(['entryPointEvidence','rightClickMenuStatus'])`. Do not export all storage. Codes distinguish unavailable Shelf, local readiness, accepted recovery window and Chrome-blocked recovery. Stored menu status is acknowledgement evidence, not proof of OS menu visibility.
11. To test blocked recovery in a disposable worker, temporarily make both `sidePanel.open` and `windows.create` reject; click the toolbar, inspect `ACCESS_BLOCKED` and the action tooltip. No visible interface can be promised when Chrome rejects both routes. Restore methods or reload.

Record Chrome/OS version, fresh versus upgrade profile, each result, window count, native-menu observation and any sanitized error code. Existing automated evidence does not complete these manual steps. If REDOWN and other extensions both lose their native menus, record that separately as potential browser evidence.
