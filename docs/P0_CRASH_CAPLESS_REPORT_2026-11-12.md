## Demonstrated repairs and source anchors

- `extension/startup-crash-trace.js`, `storageOperation`: a latency timer now observes slowness while the writer retains the lock until actual settlement. Coalesces normal ring flushes by 50 ms and exposes latency/lock wait. Snapshot reads remain bounded. Slow eventual success no longer recursively produces a storage failure.
- `extension/entry-bootstrap.js`, `observeEntryJournal` / `boundedEntry`: the journal queue likewise retains actual promise ownership after the warning deadline. Suppresses healthy trace-about-journal pairs, retaining timeout, error and late-settlement observations. The toolbar open path still runs independently of that journal queue.
- `extension/forensic-diagnostics.js`, `health`: deduplicates/coalesces unchanged fallback health writes. Sends stable-ID events to the capless collector **before** the existing bounded mirror's retention/admission. The old mirror and existing exports remain compatible.
- `extension/service-worker.js`: loads the minimal flight core before startup/core import, initiates a tiny nonblocking epoch checkpoint, then retains the original guarded imports and single toolbar/menu ownership. No startup or save awaits archive flush.
- `extension/flight-recorder.js`: always-on small per-epoch heads; one sampled heap/event-loop observation; sanitized checkpoints and last save/proof correlation. Retains 16 tiny heads. Faults and unknown prior-worker endings pin envelopes separately; unknown can mean normal idle. The 16-envelope incident store **never silently evicts**; full/unavailable signals incomplete, and only the explicitly confirmed incident-delete action clears it.
- `extension/capless-archive.js`: separate lazy IndexedDB store, immutable JSONL chunks, monotonically reserved sequence ranges, SHA-256 chain, event-ID ledger and unique-attempt snapshots. Durable pending reservation and atomic finalize allow restart recovery without overwriting a segment or replaying a provider write. Corrupt pending content remains preserved and blocks recovery. Strict transaction durability is requested when supported, with honest fallback; no OS fsync promise.
- `extension/capless-controls.js` / Options: OFF by default, independent of Debug Mode; native keyboard/click activation and confirmation every enable/re-enable, separate RAW confirmation. OFF stops future acceptance and preserves disk history; already accepted writes may finish. Status exposes backend, cached sequence/count/bytes/backlog/error/incomplete; inspect provides quota estimate where available. Archive failure opens the panel to expose the warning.
- Complete archive export uses a user-gesture File System Access picker and streamed ZIP entries with backpressure where available; otherwise bounded multipart ZIPs. Includes per-part manifests, hashes, gaps, pending unconfirmed journals and pinned envelopes. Keep all parts. Snapshot boundary excludes newer writes; pending journals can change during export. Turn recording OFF and let queued writes settle for a quieter export. A generated download is not asserted to have reached disk.
- `background.js` adds only an observational receipt hook using the existing `isVerifiedReceipt` validator. Provider dispatch, independent verification, counters, History and retry state machines are untouched. `forensic-download.js` adds a privacy-safe flight snapshot to RAW/SECURE exports. Original seven-file bundle builders, manifest/CSP/permissions, 3D-disabled behavior and vendored viewer code remain unchanged.

There is **no application retention cap, TTL or automatic deletion** in the capless archive. Memory stays bounded at 256 events / 1 MiB (128-event, target 64 KiB writer batches). Overflow creates an explicit loss gap where persistence is possible. Write failure marks unconfirmed ranges/stalled state and preserves prior committed data. Logging never retries a cloud transfer. Existing compact compatibility rings remain bounded; complete capless history is exported with the new complete-archive button, not misrepresented as fitting an old bounded export.

Archive history begins only after confirmed opt-in. Old pruned records cannot be recovered. Account/source correlations use an archive-local HMAC key, excluded from exports. Source website is distinct from destination provider; Google Drive is not Google Search. Unique attempt IDs and independently validated proof determine verified counts; stage COMPLETED alone does not. Counts can be filtered by site/provider/opaque account/UTC date. Rates are deliberately null because lifetime coverage is unknown.

## Privacy, storage and operational limits

SECURE is default. Default events use typed fields and allowlisted bundled stack frames; no private URLs, names, tokens, raw errors or sensitive account IDs. Confirmed RAW preserves the existing forensic metadata whitelist, potentially including signed URLs and original errors, as plaintext in the Chrome profile. It is not separately encrypted. Profile/OS access control is the storage boundary; complete archive export requires a privacy warning. No server upload, native app, policy bypass, broader permission or cloud resource is introduced.

Browser-managed IndexedDB is actual on-disk storage, subject to finite quota, eviction, user clearing and OS/process termination. Extensions cannot silently write arbitrary Windows folders. File picker grants are optional and their loss aborts export without deleting source data; multipart fallback requires reviewed clicks. A tiny epoch write is initiated before core import, but a hard kill can beat any asynchronous commit. It cannot promise an after-death stack.

The small epoch-head discovery uses one local.get(null) at worker activation and trusted snapshot inspection, then projects only recorder keys. It never exports other storage values. This has a resource cost worth measuring on the owner's real profile. Status reports the largest observed collector backlog, not a globally atomic count across contexts. Archive corruption and lost storage identity fail closed rather than recreate history. Incomplete capture may remain conservatively marked after recovery; historical gap records are not erased to make the status look green.
