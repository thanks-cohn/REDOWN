It does not attach a direct R2 custom domain or merely save text. Feedback and the former hardcoded folder URLs were Debug-only; UI then overwrote background-saved profiles and claimed public serving without any public connection check.

Now Normal Mode explains this public-delivery action and shows progress/results. Attachment reads back the exact hostname + Worker association before saving it; an interrupted/missing read-back reports Unknown. CORS/deployment failures after association report Needs setup, preserved across reload. The background reloads before changing one destination; Settings no longer overwrites its result with an older profile list. A bounded unauthenticated GET checks public Worker health separately; verified **connection** never means an individual file exists. CORS/extension host permissions may prevent that public probe, in which case association remains Attached with explicit unverified DNS/SSL guidance. No additional host permission or Cloudflare authorization scope was introduced.

New `cfPublicAddresses` performs read-only managed `r2.dev`, R2 custom-domain, and exact Worker-domain discovery. It never prepares/deploys/enables storage. No addresses means no disclosure. Authenticated private blob previews/lightbox remain independent. Existing private “Open original file” remains separate from public URL information.

## Stage 3: Explorer operation reliability

### Source-confirmed causes and fixes

- Embedded Worker management used `cleanPrefix`, an **upload naming sanitizer**, to find existing files. Unicode, punctuation, spaces at segment edges and repeated separators could identify another/nonexistent key. Exact object keys now remain exact across properties, signed/private reads, transfer, delete and rename. Upload/remote-ingest naming remains its existing separate contract. Background folder prefixes preserve repeated separators. Incomplete/cyclic/over-limit folder listings stop before mutation instead of pretending a partial enumeration was complete.
- Worker `transferBatch` wrote unconditionally and immediately reported copied; the background accepted any nonempty destination key, then deleted move sources. Copies now use conditional create (or conditional ETag replace only after explicit conflict choice), read back destination size/ETag/version against the completed R2 receipt, and validate MD5 where available. They preserve HTTP/custom metadata, including cross-Worker metadata transport. Source read versions and destination receipts are validated in the background, including keep-both filename form. Moves recheck source and destination size/ETag/version before deletion and confirm absence afterward. Failed/incomplete receipts never authorize deletion; source-delete failures are counted separately from copies. History rename uses the same verified copy-before-delete approach.
- Existing Worker compatibility check only probed an empty `ensurePrefixes`, which demonstrated none of the necessary transfer guarantees. Profiles now require **Worker v5** and explicit authenticated capabilities. Deployment health must report that version and safe-transfer support before saving. A v5 connection probe has an eight-second deadline; network/403 errors do not trigger needless deployment. Operation requests retain 30-second deadlines, and ambiguous writes are not replayed. A definitive 401 may still repair and retry once under the existing preparation contract.
- Properties and Copy public URL used Worker preparation unnecessarily. Properties now reads an exact object match through OAuth listing metadata, normalizes API field names, preserves zero-byte sizes and captures source identity; an older account/bucket response cannot replace a newer view. Public-URL actions use Stage2's read-only address model; the menu waits for configuration and disables unavailable links. No fabricated public URL appears in private properties.
- Generic `friendlyError` and count-only summaries hid reasons. Errors now retain HTTP/auth/setup/verification explanations and safe recovery steps. Retry results preserve earlier failures. Worker requests contribute bounded passive `api.read`/`api.write` events to Debug runtime diagnostics, without object names, URLs, tokens or bodies. Existing schemas/version/boundaries remain unchanged. Feedback renders literal text, not filename/error HTML; an older dismissal timer cannot clear a newer operation.
- Normal Download already used direct authenticated Cloudflare reads rather than the old background signed-URL path; its source/key/filename route is retained. New terminal-state handling reports completion and prevents an interruption racing initial Chrome lookup from being overwritten with “Downloading”. Chrome acknowledgement still is not content verification.
- Archive entries are virtual, but the menu offered destructive R2 operations and ordinary file downloading. Rename/Move/Delete now explicitly explain extraction is required; keyboard paths enforce the same limits. Archive Download uses its actual containing archive entry URL. Extraction uses conditional verified writes and cannot silently overwrite another object. Existing preview, Copy/extract and archive navigation remain.
- Inline rename/folder creation capture the original source instead of consulting a changed active view when committed. Clipboard operations retain the captured selection/source and avoid clearing a newer clipboard; conflict retries retain previous failures.

These are **source-confirmed defects**, with reproduction in controlled fixtures. The user-specific red warning text has not been supplied; its exact deployed authentication/Worker failure remains undiagnosed. No claim is made that every reported deployed warning has been reproduced or closed.

Remaining limitations are explicit, not waived:

1. Administrator policy blocks unpacked extension installation: no installed Chrome workflow assertion, actual download, OS clipboard, OAuth expiry/soak or real extension/background messaging proof. Browser fixtures are not a workaround for that gate.
2. No selected live test account/buckets/fixtures were exercised, no customer Worker deployed and no actual domain attached. Deployed v4 users require the normal v5 preparation/repair workflow before safe mutations. API permissions, deployment propagation, DNS/SSL, large live transfers, multiple real accounts and byte/hash truth still require the [live checklist](runtime/THREE_STAGE_LIVE_CHECKLIST.md). User's exact red messages remain unavailable.
3. R2 binding deletion has no atomic conditional-delete argument. Version/ETag/size checks and destination confirmation narrow races but **cannot exclude another client writing between the last check and deletion**, or atomically preserve a destination modified immediately afterward. Moves/renames are not transactions; avoid concurrent editing of the same keys during the live validation. No blind retry follows an ambiguous write/delete. Multipart objects without MD5 rely on completed R2 write receipt + size/ETag/version read-back, not an independent full content hash.
4. Very large/slow transfers may exceed the bounded request window; the UI reports unknown and preserves sources when copying is unconfirmed. No durable background job/resume or universal large-object performance claim is added.
5. Seven baseline test defects, license drift and broader readiness gates remain. Stable Upload/remote download/Beta/Debug behavior passed relevant local regressions but is not live-certified by this change.
