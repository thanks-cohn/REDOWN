# Three-stage live acceptance still required

Use an administrator-approved Chrome environment; do not bypass unpacked-extension policy. The audit ZIP is not a store release. Resolve licensing before release packaging. See [actual local results and limits](../THREE_STAGE_REPAIR_REPORT.md).

1. Load reviewed source/package through an allowed installation route. Record commit/package hash and extension version. Toggle Beta and Debug independently, restart Chrome and confirm persistence. Confirm simulation is Debug-only.
2. Select an explicitly authorized disposable account and two disposable buckets/prefixes (and, if available, a second authorized account). Never use ordinary user objects. Enable Debug passive collection; export the bounded support bundle and note correlation IDs from `sendMessage` responses. The offline runtime CLI can inspect the exported bundle; it cannot operate Chrome or Cloudflare. Collector records no object keys/tokens and resets on service-worker restart.
3. Create byte-known disposable files: zero-byte, small text, image, nested paths, Unicode/spaces/#/?/%, larger object and a ZIP with known entries. Record independent hashes and HTTP/custom metadata. Keep an unrelated sentinel in each bucket. Test strict private buckets too. Do not concurrently edit the same source/destination keys during move/rename.
4. Validate one/multi/120-bucket layouts at1366×768 and narrow sizes with actual buckets or approved local fixture. Confirm expansion stays inside Storage and pushes Destinations downward, first/last rows scroll, Escape/keyboard/reduced motion work.
5. For an authorized unused Cloudflare-hosted hostname, Attach explicitly publishes REDOWN Worker `/assets/` delivery. Compare PUT and exact GET association, actual saved profile and page reload. Distinguish accepted association, DNS/SSL setup and public Worker connection. Never infer object accessibility from these. Test pending/rejection/interrupted response safely; inspect Cloudflare before repeating an ambiguous attach. Direct R2 custom/managed domains remain distinct. Validate all four disclosure combinations; a disabled domain is labeled unavailable. Do not enable public access on private customer data to satisfy a test.
6. Run each operation in the report matrix through real right-click menus. Verify actual Chrome download content/hash and filename; verify system clipboard URL contents; verify every copied destination content/hash/metadata and original retention. For moves/renames verify destination first, then source absence; record conflicts and cancellation. Explicit Replace is opt-in; check keep-both/skip separately. Delete only fixtures after confirmation; verify the unrelated sentinel remains. Verify archive edit controls are unavailable and extraction cannot overwrite an existing fixture.
7. Switch buckets/accounts/files during pending reads, refresh and retry failures, interrupt network/auth using disposable operations, inspect warnings and support traces. Unknown writes require destination inspection, never blind retry. Verify source/destination changed-version refusal. Record the residual non-atomic deletion race as a limitation, not a transaction guarantee.
8. Restore private/public settings and remove only authorized fixtures after recording results. Keep operation-by-operation installed browser and live Cloudflare columns separate. Close each acceptance criterion only after its actual evidence exists; failures/blockers remain open.
