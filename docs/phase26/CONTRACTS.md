# Universal foundation contracts

Provider contract `1.0.0` is separate from file API `0.3.0` and scoped transport `1.0.0`. Existing 0.2 requests/jobs and the 0.1 simulation facade remain compatibility surfaces. The published JSON Schemas are `extension/file-engine/provider.schema.json` and `schema-0.3.json`; generated browser-safe validators come from `scripts/phase26/compile-contracts.mjs`. CI checks generated drift.

An identity contains `provider`, `account`, `container`, and either the legacy exact `key` or an adapter-owned `locator` map. Locator values are bounded strings; their meaning belongs to the adapter. Names are display metadata, never universal identity. Roots and child construction, equality, containment, metadata matching and names belong to the identity model. Provider/account/container routing permits multiple scoped instances of the same adapter implementation. The reference store keeps their data separate.

Metadata carries size, revision, folder classification, content type and optional timestamps/provider semantics. Revisions are provider observations, not universal content hashes. Integrity receipts use SHA-256 over actual readback bytes. ETag is not treated as SHA-256. Native duplicate names remain separate by ID; a non-unique name lookup returns `AMBIGUOUS_IDENTITY`. Case matching and normalization are declared by the adapter. Local reference semantics require an owner-exclusive Linux sandbox; they do not establish safety for an adversarial host mount.

Every provider describes directory model, case matching, duplicate names, stable IDs, search/list/pagination, ranges, streaming, multipart, server operations, conditions, checksum algorithms, metadata, links/trash/notifications, quota/rate-limit availability and authentication methods. False features and unsupported operations remain explicit. Only actual primitives and established safety capabilities may be composed; a missing conditional source delete blocks a move. Native-ID rename is unsupported until a stable-ID-preserving primitive exists.

The coordinator retains canonical planning, idempotency reservation, journal lifecycle, readback verification, cancellation, recovery and Resource Atlas instrumentation. The 0.3 operation-body module uses those existing facilities; legacy 0.2 bodies remain for compatibility. Unifying the remaining duplicated operation-body logic, global queue budgets, streamed scheduling and general resumability remain acceptance gaps. No complete alternate transfer engine lives in an adapter or Python.

Owner scopes intersect engine authority and per-child checks. Adapter containment enforces opaque location scopes, while registry roots bound allowed locations. Session-owned job IDs do not override revocation or grant global recovery. Process possession is the stdio capability. The owner bootstrap uses secret environment references for the current leased R2 adapter; a full universal expiring/renewable credential registry is unfinished.

`extension/file-engine/providers.json` registers discovery/source/test obligations. AAC reads it generically, so a new registration gains inventory entries without another AAC core edit. The baseline in `tests/providers/baseline.mjs` is mandatory, with provider-specific negative tests extending it. Discovery registration earns no execution or certification credit. Independent persisted-byte/filesystem or live oracle evidence remains separate from an engine success receipt.

Optional capability additions should preserve existing requests and meanings. Reject incompatible contract versions. New required identity/authorization semantics require a new version, old/new compatibility tests, documented migration and preservation of Purpose-Preserving Reconstitution obligations. Provider extension data belongs under a namespaced `extensions` map. Unsupported primitive families (trash, restore, sync, notifications, resumability and others) are declared; a declaration is not an implementation promise.
