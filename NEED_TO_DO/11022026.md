## P0 — Make Google Drive as seamless as the other clouds

- [ ] **P0.1 — Audit and eliminate the special Google Drive transfer tab.** Current Google Drive flow still opens a browser-mediated transfer page and asks users to keep it open. Inspect and document the real Chrome MV3 service-worker/content-script/offscreen-document constraints and the existing Google Drive API upload pipeline. Target experience: the owner signs in once, then **right-clicks a supported file → REDOWN → Google Drive → saved**, with no transfer page, no separate foreground tab, no repeated permission confirmation during a healthy authorized session, and no mandatory user interaction after the save command. Show progress in the Shelf/History without requiring the Shelf to stay open. Never claim browser-side work is running after a terminated service worker unless its resumable state and recovery are truly implemented.
- [ ] **P0.2 — Remove REDOWN's artificial 32 MiB file cap; stream and resume large supported files.** Determine Google Drive's real current upload API limits, resumable-session constraints, maximum per-request chunk sizes, available memory, signed/authenticated source limitations, and Chrome extension lifecycle. Support files as large as the permitted service and browser transfer path can safely handle, ideally approaching Drive's service maximum when actually testable. No in-memory whole-file buffering, invented unlimited support or false completion. Verify small, large, interrupted, resumed and uncertain transfers with accurate byte counts and durable receipts.
- [ ] **P0.3 — Save to the selected Drive root, never create an unwanted REDOWN folder.** No automatic `REDOWN`, `Apps`, or similar folder just to perform a normal save. Respect only explicitly authorized Google Drive scopes and actual accessible files/folders (prefer `drive.file` as the owner's public-app verification goal). Do not scan or modify a user's entire Drive or silently request broader access to implement root saving. If the chosen scope cannot support an operation, disclose the limitation and use the least-privilege supported flow; do not pretend consent or provider capabilities exist.
- [ ] **P0.4 — Keep source provenance private to REDOWN.** Gather the original source/page/frame/link URLs inside REDOWN as necessary to capture bytes and maintain trustworthy History; **never add those source URLs to Google Drive API upload metadata**. Google receives only the requested content, filename and minimal required destination metadata. A browser-fetched source still reveals ordinary network information to its origin server; do not promise network anonymity. Avoid extra provider permissions, prompts and unrelated tracking.
- [ ] **P0.5 — First-run and reconnection UX.** One deliberate Google OAuth authorization, persistent session with safe token refresh when permitted, and repeat right-click saves until genuine revocation/expiry requires reconnection. Handle inaccessible URLs, cookies/authenticated sources, redirects, blob/media objects and failed origins truthfully; never present `data:`, `blob:`, protected streams or cross-origin captures as universally available without proven byte access. Keep source-capture constraints independent of the Google Drive upload API.
- [ ] **P0.6 — Native menu isolation and reliability.** Preserve the protected V3 right-click engine, native shared menu authority, Cloudflare R2 TRUE REMOTE implementation, Dropbox/OneDrive integrations and provider-local Home behavior. Changes to Drive must be isolated, additive and evidence-backed. Handle cancel/retry/resume, Keep Both conflicts, file extensions, extensionless filenames, and exact History **GO TO** to the verified saved Drive object. No accidental Google Drive folder creation or cross-cloud routing.
- [ ] **P0.7 — Acceptance before checking this item complete.** Test fresh Chrome profile/install, connected session, repeated right-click saves, browser closed/reopened, service-worker suspensions, network interruption, small and multi-GB transfer when testable, filename/extension integrity, root placement, private metadata, History receipts/GO TO, no unwanted transfer tab, no recurring permission prompts, and concurrent sessions. Record actual API requests (with secrets redacted), SHA-256 or appropriate integrity evidence, saved Drive file ID and read-back confirmation. Mark unsupported source types explicitly; test on real installed Chrome, not just unit mocks.

**Owner's experience standard:** Google Drive should feel like Cloudflare, Dropbox and OneDrive from the Shelf: **connect once, right-click, save, and go about your day.** This is a quality target, not a claim that other providers are already defect-free.
