## 0. The governing product principle: beautiful personal sanctuaries

REDOWN should not merely be a place to send, list and move files. Users should be able to **make beautiful, persistent spaces out of their own collections** and return because those spaces reflect their taste, memories and interests. Keep the originals portable and untouched; store reusable presentations, captions and settings independently so aesthetic attachment comes from ownership and creative agency, not lock-in. Make the inexpensive entry point genuinely useful, keep baseline reliability free, and never mistake an attractive screenshot for working file operations.

## 1. P0 FIRST AND FOREMOST: make the compact LEFT pop-out / Split View Explorer actually work

### 1.1 Owner's immediate complaint

The current attempt to put REDOWN on the left compresses the **entire full-size Dashboard** into a narrow space, creating a visually incoherent pile of tiny controls. **Do not shrink the dashboard. Build a deliberate, purpose-designed compact layout for the available width.** The requested experience is a useful, polished miniature REDOWN workspace, not an iframe-sized copy of the desktop.

This requirement combines with the previously requested **Chrome 155+ native browser Split View**, not replacement of the separate REDOWN Shelf side panel. Source and available Chrome capabilities must be checked at implementation time; use supported API feature detection, preserve the current webpage, and never claim native installed-browser acceptance from mocks.

### 1.2 The compact layout, in strict visual order

In the **left REDOWN Explorer tab of Chrome Split View**, render these distinct zones vertically, with deliberate spacing and bounded scrolling:

1. **Top persistent header:** REDOWN identity, breadcrumb/active account or bucket where relevant, and a clear **More (⋯)** menu. The More menu must expose **all existing Dashboard menu actions/options**, not drop capabilities due to narrow width; group them intelligibly, maintain keyboard access, discoverability, and working handlers. Do not simply hide functions.
2. **Primary File Explorer:** the main, immediately usable compact file list/tree with navigation, selection, search, basic sort/view controls when feasible, upload/create actions through direct buttons or the More menu, genuine bounded scrolling and pagination. Keep the selected cloud/account and folder visible; do not shrink the explorer into an unusable strip.
3. **Preview directly underneath File Explorer:** render the **currently selected exact file** using the existing preview engine, including applicable image, archive/CBZ/ZIP and other supported types. Selection updates preview; respect unsupported file types and preserve file identity and security.
4. **History underneath Preview:** useful latest saves, visible statuses, Today expanded where appropriate, and immediate GO TO for verified successful receipts. Use a compact expandable panel/list rather than compressing every entry into one row.
5. **Bottom utility area:** the **Right-click Setup** and other Dashboard utilities/settings, neatly arranged as accessible compact sections (accordion, disclosure or clearly labeled tabs as appropriate). Their actual functions, including Simple/Nested/Narrow/Level/Depth, bucket selection, Save Changes/Apply, URLs, connections and diagnostics, must remain reachable; use an optional bottom utility rail if it improves geometry.
6. **Independent scrolling/resizing:** a fixed/persistent top control strip; space-aware file list, preview and History; clearly defined minimum usable sizes and safe overflow. Prefer predictable collapsible sections and functional scroll regions over arbitrary proportional scaling.

**Conceptual mobile-width arrangement:**
```text
REDOWN                     [More ⋯]
Account / Bucket / Breadcrumb
---------------------------------
EXPLORER             [Search] [⋯]
[folders and files, bounded scroll]
---------------------------------
PREVIEW
[selected object, accessible actions]
---------------------------------
HISTORY                         [⌄]
[Today / confirmed saves / GO TO]
---------------------------------
TOOLS / RIGHT-CLICK SETUP        [⌄]
[Simple / Nested / buckets / depth]
[Save Changes / Apply / Diagnostics]
```
The diagram is a **content hierarchy**, not a rigid pixel prescription. At wider widths, allow comfortable reflow; at narrow widths, avoid overflow and clipped controls. No essential feature should disappear without an obvious accessible path.

### 1.3 Browser behavior and state ownership

- **Split mode:** Chrome main content is two actual tabs, **REDOWN on the left** and **the original webpage on the right**. REDOWN Shelf is a distinct extension side panel and must remain intact, open and usable; do not call `chrome.sidePanel.open` to implement split or redirect Shelf to Explorer.
- **Tab mode:** reuse an eligible existing REDOWN tab before creating another. **Split mode:** reuse the appropriate existing paired REDOWN Explorer tab; subsequent GO TO clicks navigate the same instance, not a new split.
- **Exact navigation:** preserve provider/account/bucket/final object key, including Keep Both names; seek the actual object across pagination, select/scroll/focus it and invoke existing preview. Failed/pending/cancelled/uncertain History rows receive no GO TO.
- **Dashboard-to-compact transition:** keep the desktop Dashboard layout as-is. Choose a distinct compact composition when width/split context demands it, reusing the same underlying functional components/state rather than copying/reimplementing storage logic.
- **Responsive transition:** test widths, orientation/resizes, Chrome split ratio changes, side Shelf simultaneously open, keyboard focus, screen readers, reduced motion, cross-window selection and interruption. Layout must not oscillate around breakpoints or reset selection, scroll, filters, preview or history arbitrarily.
- **More menu contract:** inventory every existing Dashboard action, define its compact location, and verify invocation rather than treating mere visual presence as parity. Long menus are grouped, scrollable and accessible.
- **Error truth:** preserve actual connection/errors and partial discovery in Setup/Diagnostics, not as extraneous native Chrome context-menu items.

### 1.4 Acceptance for P0

Starting with an ordinary webpage and REDOWN Shelf open, clicking a successful History GO TO in Split View yields **webpage unchanged on right, functional compact REDOWN on left, Shelf unchanged**, Explorer at the exact selected file and Preview immediately underneath. Explorer, Preview, History and bottom Right-click Setup are readable and useful at the chosen split width; **More** exposes the existing Dashboard options. Repeated GO TO updates this same compact Explorer without redundant tabs. Browser/layout/source tests and real Chrome evidence must be recorded separately; no fake live proof.

## 2. P1 SECOND: Scrolldown (Pretty), the premium immersive reader

**Target:** a saved per-directory or per-collection presentation using the existing common file/reader engine. Center the active image, document or archive reading surface; show up to **three previous and three next** neighboring document covers as a contextual carousel, with **left/right changing document** and **up/down scrolling within its pages**, and clear keyboard focus ownership. Offer **Dimmed, Glass and Black** atmospheres (plus accessible contrast/reduced-motion behavior), graceful cover-loading fallbacks and remembered reading state where practical; never download entire large archives just to decorate the screen.

### 2.1 Companion: Regular Scrolldown

Keep a straightforward, continuously vertically scrolling presentation for supported PDFs, CBZ/ZIP pages, and other readable documents, with the normal Explorer background. It is a separate mode from Pretty, not a crippled preview.

### 2.2 Additional Reader and Magazine modes

**Reader:** page-by-page sequential reading; support appropriate forward/backward controls, optional spreads and right-to-left manga direction, without silently changing file order. **Magazine:** an editorially composed image/media sequence for events and curated directories, with magazine-like hierarchy and page transitions; avoid claiming features of a full page editor until separately scoped. All modes consume the same authorized source objects, previews and metadata, with saved switchable presentation presets.

### 2.3 Acceptance

The user can switch modes without duplicating or moving the underlying files; current document identity, previous/next order and supported preview behavior remain correct. Keyboard left/right versus up/down works as specified, the cover strip gracefully handles fewer than seven items, and full-size and compact screens remain usable.

## 3. P1 THIRD: Comic World / Comic Universe

Choose an existing authorized directory and **Make Comic Universe**. Index eligible CBZ/ZIP archives (optional explicit recursion), extract/cache a suitable first-page cover via bounded/range reads, and display floating cover cards with titles on a **finite, edge-wrapping plane**, where leaving an edge returns from the opposite one. Keep the number of rendered cards virtualized and bounded; offer grid/list fallback, keyboard navigation, accessible motion controls, stable ordering and no exploding clone count.

Selecting a cover opens **the existing REDOWN archive preview/reader** with correct provider/account/bucket/key, not a new incompatible archive engine. Future enhancements: grouping by series/volume, favorites, reading progress, cover override and presentation themes. First eligible directory free; Premium Elite unlocks unlimited eligible directories subject to ordinary technical limits and transparent storage costs.

## 4. P1 FOURTH: occasions, weddings, quinceañeras and evergreen reusable galleries

### 4.1 Product: a beautiful occasion sanctuary, not just a folder of photos

Users select their existing images, supply **title, subtitle, caption, optional date/person/role/quote**, choose a design format, and create a shareable visual story for weddings, quinceañeras, sweet sixteens, birthdays, graduations, anniversaries, reunions, memorials, engagements, showers and other celebrations. Layouts are **reusable indefinitely** by swapping content without rebuilding; preserve originals and keep private-by-default permissions with explicit publication/guest-upload consent. A published gallery needs a verified hosting, share-link, bandwidth, access and deletion contract; a local presentation alone must not be described as a published website.

### 4.2 First general-purpose format: The Grand Story (TOP OCCASION FORMAT)

The first and most versatile template must work across almost every event without changing code or requiring graphic-design skills. Its reusable sequence is **Hero Cover** (title, subtitle, image, date), **Opening Moment**, **Memory Grid** (3–6 captioned images), repeatable **Spotlight Sections**, **People We Love**, renameable **Timeline/Highlights**, and **Closing Page** with thank-you and relevant share/download options. Every section can be relabeled or omitted where appropriate, with tasteful defaults for weddings and quinceañeras but no hard-coded event stereotypes.

### 4.3 Five signature reusable premium formats

1. **The Grand Story:** universal storybook gallery, hero, memories, featured scenes and closing; flagship format.
2. **The Timeline:** dated milestones and chronological photos, equally suitable for growing up, wedding preparation or family history.
3. **The Spotlight Gallery:** editorial large-image-led presentation with supporting captions and companion photos.
4. **The Celebration Grid:** high-quality responsive mosaic tiles that open into readable images and captioned detail views.
5. **The Keepsake Album:** intimate scrapbook or heirloom treatment with photographs, notes, quotes and meaningful context.

Each format uses one reusable structured content schema and saved presentation recipe; avoid five unrelated rendering engines. Support elegant themes, responsive layouts, access controls and clear image credits/ownership, with optional QR links, event-screen slideshow and guest contributions only once privacy/storage/abuse safeguards are designed.

### 4.4 Packaging and integrity

Offer a useful, beautiful **Grand Story** entry experience free or within the agreed free tier. Package five signature formats as a possible paid unlock, with **unlimited reuse of the layout templates**, but not an unlimited promise of REDOWN-hosted storage, public bandwidth or guest uploads. Proposed broad Elite pricing remains **$5/month or $12/year**, subject to costs and payment-provider rules; assess optional event-specific hosting separately before committing.

### 4.5 Acceptance

A user without design experience can make a polished wedding and a polished quinceañera by replacing images and short fields in **the same Grand Story layout**, save the work, reopen it unchanged, and share it only through the permissions explicitly chosen. Switching between the five formats retains the same underlying media/captions when structurally compatible.
