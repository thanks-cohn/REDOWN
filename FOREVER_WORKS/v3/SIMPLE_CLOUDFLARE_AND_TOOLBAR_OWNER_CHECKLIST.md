# Approved Chrome acceptance checklist

These are pending installed/visual checks. Use an approved Chrome environment; managed Chromium in the implementation workspace cannot install REDOWN. Keep existing data; use a disposable profile/source copy for failures. Do not grant broader site access to hide Chrome security notices.

1. With only a verified account's lowercase `redown` bucket available, set Simple and inspect the real page/link/image native menu. Expect REDOWN → Cloudflare, with no Buckets or management clutter. Save a harmless public HTTPS file; verify the recorded account, literal `redown` bucket and empty prefix, not Explorer's selected bucket.
2. Add Photography with an actual deep prefix. Expect Cloudflare → REDOWN first, then Photography. Save to both; verify exact account/bucket/root versus full configured prefix. Do not infer a path from the Menu Label.
3. Activate an additional eligible bucket. Its root must be a flat Cloudflare child, with no Buckets heading or further Simple directory hierarchy. Disable/remove additional participation and labels; Cloudflare must collapse back to a direct redown-root save. Saved records must not be silently deleted or renamed.
4. Test duplicate labels/accounts, absent default and revoked authorization. Targets must remain exact and distinguishable. Ambiguous accounts must offer Setup rather than selecting an arbitrary default. Verify existing explicit account setup establishes the intended default; this round adds no new default-account chooser. Narrow and Level must preserve their own existing layouts.
5. Before update, record any REDOWN-authored global/tab `!` and technical hover text. Reload the corrected extension, switch tabs/windows and restart the worker. Expect the friendly title REDOWN — Your cloud companion and no REDOWN launch exclamation. Chrome-owned permission notices can still be present.
6. With no OAuth and then with slow/unavailable OAuth, click the toolbar. Shelf must open independently of menu/cloud work. Missing readiness acknowledgement and slow or late Shelf success must not add `!`, technical hover explanations or a second interface.
7. In disposable worker DevTools temporarily wrap `chrome.sidePanel.open` to reject, then click the actual icon. Expect only the native attached mini-dashboard where supported. If `openPopup` is rejected, another click uses the armed native popup. No detached window, automatic tab or permanent preference change. Restore the method/reload.
8. Inspect local `entryPointEvidence`, `toolbarRecoveryStatus` and the recovery support export for genuine failures. No credentials or all-storage dump. Retry Shelf must close the attached popup first. Dashboard and Settings remain explicit user actions.
9. Trigger actual ordinary transfer success and failure. Their short theme-aware icon flashes/titles must remain and restore normally. Any existing legitimate progress badge must not be erased by launch cleanup. No permanent recoloring should imply unknown readiness is failure.
10. Test Level Depth5→3→5 with known branches. Force a partial listing/authentication failure in a disposable fixture; known authorized deeper paths must remain available when depth is raised again. A changed Depth while an older Reload runs must ultimately register the latest generation without a second manual Reload. Verify actual native-menu order after these changes.
11. Compare Chrome site access On click/specific/all only through the user's ordinary settings and explicit choice. “Wants access to this site” belongs to Chrome. Do not count its continued presence as a REDOWN title regression, and do not silently change permission settings.
12. Repeat fresh versus upgraded profile, browser restart, worker restart, rapid clicks, two windows and restricted Chrome pages. Record Chrome/OS/build hash, real menu screenshot, full hover screenshot, tab/window counts and exact saved-object receipt. Keep fixture results separate from installed/provider proof.

The transactional journal/checkpoint, scoped-refresh and Daily/Weekly/Off history phases remain open. Do not interpret this bounded live-memory correction as a completed Time Machine or durable mid-page journal.
