# MultCloud — REDOWN competitor brief

**Category:** web-based cloud transfer/sync/backup product  
**Priority:** P0  
**Status:** Strategy with cited starting points; manually verify product versions and feature availability before implementing claims.

## What the competitor does well
Many cloud providers, scheduled transfers, sync/backup, remote URL upload and search across connected clouds.

## What we should borrow as product principles
Long-running job scheduling, cloud account overview, unified search, task history, helpful sync policies.

## Where REDOWN could win
Make the extension the daily entry point; integrate right-click, screenshots, recordings, default shortcuts and user-owned compute when feasible.

## Where they can beat us / reality check
Very high on cloud functionality; do not portray autonomous remote jobs or multi-cloud sync as unique.

## REDOWN API and cold-agent implications
Scheduling resources, executor placement, provider consent/billing checks, cloud search, job manifests and execution audit.

## Concrete competitive / QA experiment
Same URL-to-two-cloud workflow: steps, setup, time, reliability and cost transparency.

## Rules of engagement
Maintain REDOWN's one-click DONE workflow, user-owned execution model where authorized, no false transfer or replica success, no silent destructive cleanup, auditable provider scopes and error handling, accessible simple mode, desktop expansion via shared experience. Competitor strengths are inspiration; do not copy proprietary assets or obscure needed confirmation.
